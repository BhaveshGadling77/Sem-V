PART A: SHORT ANSWER QUESTIONS (100)

Chapter 1 — Introduction (Q1–Q50)

  1. QWhat is a DBMS?
    AA collection of interrelated data plus a set of programs to access that data conveniently and efficiently.
  2. QName four applications of database systems.
    ABanking, airlines, universities, sales (also manufacturing, HR, online retail).
  3. QWhat is data redundancy?
    ADuplication of the same information across multiple files, causing inconsistency.
  4. QWhat are the three levels of data abstraction?
    APhysical, logical, and view level.
  5. QWhat does the physical level describe?
    AHow data is actually stored on disk.
  6. QWhat does the logical level describe?
    AWhat data is stored and the relationships among the data.
  7. QWhat does the view level describe?
    APart of the database relevant to a particular user, hiding other details.
  8. QDefine schema.
    AThe overall logical structure/design of the database.
  9. QDefine instance.
    AThe actual content of the database at a particular point in time.
  10. QWhat is physical data independence?
    AThe ability to modify the physical schema without changing the logical schema.
  11. QWhat is a data model?
    AA collection of tools for describing data, relationships, semantics, and constraints.
  12. QName two data models other than the relational model.
    AEntity-Relationship model, object-based / network / hierarchical model.
  13. QWhat is DML?
    AData Manipulation Language — used to access and manipulate data.
  14. QDifferentiate procedural and declarative DML.
    AProcedural specifies what data is needed and how to get it; declarative specifies only what is needed.
  15. QWhat is DDL?
    AData Definition Language — used to define the database schema.
  16. QWhat is a data dictionary?
    AA set of tables storing metadata, generated by the DDL compiler.
  17. QWhat is referential integrity?
    AA constraint ensuring a value in one relation must exist in another (foreign key constraint).
  18. QWhat is a relational database?
    AA database based on the relational model, representing data as a collection of tables.
  19. QWhat language do most commercial relational DBMSs use?
    ASQL.
  20. QWhat is logical database design?
    ADeciding the database schema — the relation schemas and their attributes.
  21. QWhat is physical database design?
    ADeciding the physical layout/storage structures of the database.
  22. QWhat is an entity in the ER model?
    AA "thing" or "object" distinguishable from other objects.
  23. QWhat is a relationship in the ER model?
    AAn association among several entities.
  24. QWhat are object-relational data models?
    AModels extending the relational model with object orientation and complex (non-atomic) attribute types.
  25. QWhat does XML stand for?
    AExtensible Markup Language.
  26. QWho defined XML?
    AThe World Wide Web Consortium (W3C).
  27. QWhat is the storage manager responsible for?
    AInterfacing with the file manager and efficiently storing, retrieving, and updating data.
  28. QName three issues handled by the storage manager.
    AStorage access, file organization, indexing and hashing.
  29. QList the three steps of query processing.
    AParsing and translation, optimization, evaluation.
  30. QWhat does the query optimizer use to choose an execution plan?
    AStatistics about the relations/data.
  31. QWhat is a transaction?
    AA collection of operations performing a single logical function in a database application.
  32. QWhat does transaction management ensure?
    AThe database stays consistent despite system and transaction failures.
  33. QWhat does the concurrency-control manager do?
    AControls interaction among concurrent transactions to preserve consistency.
  34. QList four types of database architecture.
    ACentralized, client-server, parallel (multiprocessor), distributed.
  35. QWho are application programmers?
    AUsers who interact with the system through DML calls embedded in a host language.
  36. QWho are naive users?
    AUsers who invoke existing application programs (e.g., bank tellers, web users).
  37. QWho are sophisticated users?
    AUsers who form requests directly in a database query language.
  38. QWhat is the role of a DBA?
    ACoordinates all activities of the database system.
  39. QList three duties of a DBA.
    ASchema definition, granting user authority, specifying integrity constraints.
  40. QWho is credited with defining the relational data model, and when?
    ATed Codd, late 1960s/1970s.
  41. QWhich two research prototypes implemented the relational model?
    AIBM's System R and UC Berkeley's Ingres.
  42. QWhat became the industry-standard query language in the 1980s?
    ASQL.
  43. QWhat characterized databases in the 1990s?
    ALarge decision-support/data-mining apps, multi-terabyte warehouses, emergence of Web commerce.
  44. QHow do application programs typically access a database?
    AThrough embedded SQL or an API such as ODBC/JDBC.
  45. QGive an example of an integrity constraint.
    Aaccount_balance > 0.
  46. QWhat can uncontrolled concurrent access cause?
    AData inconsistency (e.g., lost updates).
  47. QWhat does atomicity of updates mean?
    AA transaction either completes fully or has no effect at all.
  48. QWhat are domain constraints?
    AConstraints restricting the permitted values of an attribute.
  49. QWhat is an assertion in DDL?
    AA general integrity constraint the database must always satisfy.
  50. QWhat does a two-tier architecture consist of?
    AA client (application) and a server (database system) connected via a network.

Chapter 6 — Entity-Relationship Model (Q51–Q100)

  1. QDefine entity set.
    AA set of entities of the same type sharing the same properties.
  2. QDefine relationship set.
    AA set of relationships of the same type among entities from given entity sets.
  3. QWhat is the degree of a relationship set?
    AThe number of entity sets participating in it.
  4. QWhat is a binary relationship?
    AA relationship set involving exactly two entity sets.
  5. QGive an example of a ternary relationship.
    Aworks_on, relating employee, job, and branch.
  6. QWhat is a simple attribute?
    AAn attribute that cannot be divided into subparts.
  7. QWhat is a composite attribute?
    AAn attribute divisible into subparts (e.g., name → first_name, last_name).
  8. QWhat is a single-valued attribute?
    AAn attribute with only one value per entity.
  9. QWhat is a multivalued attribute?
    AAn attribute that can have multiple values (e.g., phone_numbers).
  10. QWhat is a derived attribute?
    AAn attribute computed from other attributes (e.g., age from date_of_birth).
  11. QWhat is the domain of an attribute?
    AThe set of permitted values for that attribute.
  12. QDefine super key.
    AA set of one or more attributes whose values uniquely determine each entity.
  13. QDefine candidate key.
    AA minimal super key.
  14. QDefine primary key.
    AThe candidate key chosen by the designer to uniquely identify entities.
  15. QWhat forms the super key of a relationship set?
    AThe combination of primary keys of the participating entity sets.
  16. QWhat shape represents an entity set in an ER diagram?
    ARectangle.
  17. QWhat shape represents a relationship set?
    ADiamond.
  18. QWhat shape represents an attribute?
    AEllipse.
  19. QHow is a multivalued attribute drawn?
    AAs a double ellipse.
  20. QHow is a derived attribute drawn?
    AAs a dashed ellipse.
  21. QHow is a primary key attribute indicated in an ER diagram?
    ABy underlining it.
  22. QWhat is a "role" in a relationship?
    AA label showing how an entity participates in a relationship, especially when an entity set appears more than once.
  23. QWhat are the four mapping cardinality types?
    AOne-to-one, one-to-many, many-to-one, many-to-many.
  24. QWhat does total participation mean?
    AEvery entity in the entity set participates in at least one relationship.
  25. QWhat does partial participation mean?
    ASome entities may not participate in any relationship.
  26. QHow is total participation shown in an ER diagram?
    AWith a double line.
  27. QWhat alternative notation expresses participation/cardinality constraints?
    ACardinality limits like 0..* or 1..1 on the connecting lines.
  28. QWhat is a weak entity set?
    AAn entity set that has no primary key of its own.
  29. QWhat does a weak entity set depend on?
    AAn identifying (owner/strong) entity set.
  30. QWhat is a discriminator (partial key)?
    AThe attribute set that distinguishes entities within a weak entity set.
  31. QHow is a weak entity set drawn?
    AAs a double rectangle.
  32. QHow is the identifying relationship drawn?
    AAs a double diamond.
  33. QHow is the discriminator underlined?
    AWith a dashed line.
  34. QWhat forms the primary key of a weak entity set?
    AThe owner's primary key plus the weak entity's discriminator.
  35. QWhat is specialization?
    AA top-down process designating subgroupings within an entity set.
  36. QWhat is generalization?
    AA bottom-up process combining entity sets sharing features into a higher-level entity set.
  37. QHow is the ISA relationship drawn?
    AAs a triangle labeled ISA.
  38. QWhat is attribute inheritance?
    AA lower-level entity set inherits all attributes and relationships of the higher-level set.
  39. QWhat is a disjoint constraint?
    AAn entity can belong to only one lower-level entity set.
  40. QWhat is an overlapping constraint?
    AAn entity can belong to more than one lower-level entity set.
  41. QWhat is a total generalization constraint?
    AEvery higher-level entity must belong to at least one lower-level entity set.
  42. QWhat is a partial generalization constraint?
    AA higher-level entity need not belong to any lower-level entity set.
  43. QWhat is aggregation?
    ATreating a relationship set as an abstract entity so it can participate in another relationship.
  44. QWhy is aggregation used?
    ATo eliminate redundancy that arises when a relationship must itself participate in another relationship.
  45. QHow does a strong entity set reduce to a schema?
    ATo a schema with the same attributes as the entity.
  46. QHow does a weak entity set reduce to a schema?
    ATo a schema with its own attributes plus the identifying strong entity's primary key.
  47. QHow is a many-to-many relationship set represented as a schema?
    AAs a schema with the primary keys of both entity sets plus any descriptive attributes.
  48. QHow can a one-to-many relationship be represented without a separate schema?
    ABy adding the "one" side's primary key as an attribute on the "many" side.
  49. QHow are composite attributes represented in a relational schema?
    ABy flattening them into one column per component.
  50. QHow is a multivalued attribute represented in a relational schema?
    AAs a separate table with the entity's primary key and the attribute, one row per value.

PART C: SQL PRACTICE QUERIES

Reference schema (bank example, from Chapters 1 & 6)

customer(customer_id, customer_name, customer_street, customer_city)
account(account_number, branch_name, balance)
loan(loan_number, branch_name, amount)
depositor(customer_id, account_number)
borrower(customer_id, loan_number)
branch(branch_name, branch_city, assets)
employee(employee_id, employee_name, branch_name, salary)

Easy (10)

  1. List the names of all customers. SELECT customer_name FROM customer;
  2. Find all customers living in 'Harrison'. SELECT * FROM customer WHERE customer_city = 'Harrison';
  3. List account numbers with balance greater than 1000. SELECT account_number FROM account WHERE balance > 1000;
  4. Find branch names located in 'Brooklyn'. SELECT branch_name FROM branch WHERE branch_city = 'Brooklyn';
  5. List all loans with their amounts, sorted by amount descending. SELECT loan_number, amount FROM loan ORDER BY amount DESC;
  6. Find the total number of customers. SELECT COUNT(*) FROM customer;
  7. List the distinct cities where customers live. SELECT DISTINCT customer_city FROM customer;
  8. Find the average balance of all accounts. SELECT AVG(balance) FROM account;
  9. List employees earning more than 50000. SELECT employee_name FROM employee WHERE salary > 50000;
  10. Find customer names starting with 'J'. SELECT customer_name FROM customer WHERE customer_name LIKE 'J%';

Medium (10)

  1. Find the names of all customers who have an account at the bank. SELECT DISTINCT c.customer_name FROM customer c, depositor d WHERE c.customer_id = d.customer_id;
  2. Find customers who have both a loan and an account. SELECT customer_name FROM customer WHERE customer_id IN (SELECT customer_id FROM depositor) AND customer_id IN (SELECT customer_id FROM borrower);
  3. Find total balance of accounts at each branch. SELECT branch_name, SUM(balance) AS total_balance FROM account GROUP BY branch_name;
  4. Find branches with more than 5 accounts. SELECT branch_name FROM account GROUP BY branch_name HAVING COUNT(*) > 5;
  5. Find names of customers who have a loan at the 'Perryridge' branch. SELECT c.customer_name FROM customer c JOIN borrower b ON c.customer_id = b.customer_id JOIN loan l ON b.loan_number = l.loan_number WHERE l.branch_name = 'Perryridge';
  6. List each customer's name with their total number of accounts. SELECT c.customer_name, COUNT(d.account_number) AS num_accounts FROM customer c JOIN depositor d ON c.customer_id = d.customer_id GROUP BY c.customer_name;
  7. Find branches whose average account balance exceeds 1200. SELECT branch_name, AVG(balance) FROM account GROUP BY branch_name HAVING AVG(balance) > 1200;
